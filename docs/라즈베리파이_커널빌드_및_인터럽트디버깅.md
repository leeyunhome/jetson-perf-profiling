# 라즈베리파이 커널 빌드 — 실습 환경 준비 과정 (진행 중)

> 이 문서는 진행 중인 실습을 시행착오 순서대로 기록한다. 빌드/설치/인터럽트 디버깅 결과는 이어서 추가 예정.

## 목표

Raspberry Pi 4B에서 실행 중인 커널(`6.12.25+rpt-rpi-v8`)과 최대한 동일한 소스로 **직접 빌드/설치**해, 디버그 심볼이 붙은 커널을 확보한다. 이걸로 앞서 막혔던 `crash` 유틸리티(`/usr/lib/debug/boot/` 부재로 실패)를 다시 시도하고, threaded IRQ·softirq 서브시스템을 코드 레벨에서 검증하는 게 최종 목표다.

## 환경

- Raspberry Pi 4B Rev 1.2, 4코어, RAM 1.8Gi(2GB), swap 511Mi
- 커널: `6.12.25+rpt-rpi-v8` (aarch64, Raspberry Pi Foundation 표준 빌드)
- 저장공간: 102GB 여유 (`/dev/mmcblk0p2`, 117G 파티션)
- OS: Debian(Raspbian) Bookworm, `/boot/firmware/` 레이아웃(구형 `/boot/` 직접 방식이 아님)

## 시행착오

### 1. `rpi-source` 도구 — Python 2 유산이라 즉시 실패

Raspberry Pi Foundation이 "실행 중인 커널과 정확히 일치하는 소스"를 자동으로 받아오는 공식 도구가 있어서 시도했으나:

```
File "/usr/local/bin/rpi-source", line 111
    except urllib2.HTTPError, e:
SyntaxError: multiple exception types must be parenthesized
```

Python 2 문법(`except X, e:`)으로 작성된 오래된 스크립트라 이 시스템의 Python 3에서 바로 죽는다. 오랫동안 유지보수가 끊긴 도구로 판단, **수동 git clone으로 전환**.

### 2. 수동 clone은 성공, 브랜치 `rpi-6.12.y`

```
git clone --depth=1 -b rpi-6.12.y https://github.com/raspberrypi/linux .
```

258MB 다운로드, 87,451개 파일 체크아웃. 완료 후 `git log`로 커밋 시각 확인.

### 3. `make bcm2711_defconfig` 실패 — `flex` 누락

```
LEX     scripts/kconfig/lexer.lex.c
/bin/sh: 1: flex: not found
make[1]: *** [Makefile:696: bcm2711_defconfig] Error 2
```

`bison`과 함께 설치 후 재시도하여 해결.

### 4. `oldconfig` vs `defconfig` — 두 가지 유효한 경로

처음엔 "실행 중인 커널의 `/proc/config.gz`를 재사용 + `make oldconfig`"로 진행하려 했으나, 이 커널은 `CONFIG_IKCONFIG_PROC`가 꺼져 있어 `/proc/config.gz` 자체가 없었다 (`/boot/config-<버전>`은 존재).

한편 이미 `make bcm2711_defconfig`가 성공해서 `.config`가 만들어진 상태였는데, **이건 `oldconfig`가 필요 없는 별개의 경로**다 — `defconfig`는 기존 설정과 무관하게 템플릿에서 새로 생성하고, `oldconfig`는 기존 설정을 새 소스 버전에 맞게 증분 갱신하는 것이라 애초에 같이 쓸 이유가 없다. 두 방법을 섞어서 혼선이 있었으나, **네이티브 빌드(크로스컴파일 아님)에서는 `make`가 호스트 아키텍처(`aarch64`)를 자동 인식**하므로 `bcm2711_defconfig`도 arm64용으로 정상 생성됨을 확인.

### 5. 문서의 `KERNEL=kernel7l`은 이 장비에 안 맞음 (32비트용)

공식 문서의 안내 순서를 따라가다 `KERNEL=kernel7l`을 설정했는데, 이 값은 **32비트 ARMv7** 커널 이미지 이름이다. 이 장비는 `aarch64`(64비트)로 부팅 중이라 올바른 값은 `kernel8`이다. 다행히 이 시점엔 이 변수가 아직 어디에도 쓰이지 않아 실질적 영향은 없었음 — 설치 단계에서 파일명을 명시적으로 지정할 때만 문제가 될 상황이었다.

### 6. 디렉터리 구조를 책과 맞추기 위한 재구성

`git clone ... .`(현재 디렉터리에 바로 clone)으로 진행해 `rpi_kernel_src/` 바로 아래 소스가 풀렸는데, 참고 중인 책은 `cd linux`로 하위 폴더 진입을 전제로 한다. `rpi_kernel_src/linux/`로 전체를 재배치해 구조를 맞춤 (같은 파일시스템 내 이동이라 빠르게 완료).
